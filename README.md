# SSH Tunneler

Минималистичное приложение на .NET 10 и Avalonia для Windows и macOS (Apple Silicon)
для быстрого подъёма SSH-туннелей к ресурсам, замаппленным на `127.0.0.1` на удалённых серверах.

Полупрозрачное окно поверх всех окон: одна кнопка на ресурс, клик — туннель поднят,
статус виден, ресурс открыт в браузере. Повторный клик — туннель закрыт.

## Возможности

- Серверы (SSH-доступы) и ресурсы (проброс портов) настраиваются в приложении.
- Кнопка на каждый ресурс со статусом: серый — выключен, жёлтый — подключается,
  зелёный — работает, красный — ошибка (текст ошибки в тултипе и в строке состояния).
- ПКМ по кнопке: открыть в браузере, копировать URL, переподключить, отключить,
  показать лог, перейти к настройкам ресурса.
- Окно настроек не закрывается случайно: Enter не сохраняет форму, а Escape и ✕
  спрашивают подтверждение, если есть несохранённые изменения.
- Автоподбор свободного локального порта либо фиксированный порт.
- Автопереподключение упавших туннелей с нарастающей паузой (2/5/15/30 с).
- Кнопка ✕ в шапке сворачивает окно в трей (на macOS — в строку меню), приложение
  продолжает работать; выход — только через меню иконки, он гасит все туннели.
- Меню иконки: список туннелей со статусами, «Отключить все», настройки, выход.
  На Windows клик по иконке показывает или прячет окно, на macOS для этого есть пункт меню.
- Автозапуск при входе в систему, старт свёрнутым, автоподключение выбранных туннелей.
- Прозрачность регулируется в настройках или Ctrl + колесо мыши (на macOS — Cmd + колесо)
  прямо на окне.
- Панель лога с выводом `ssh -v` по каждому туннелю, сохраняется и после обрыва.

## Хранение настроек

Настройки — один JSON-файл `config.dat`, целиком зашифрованный для текущего пользователя:

- **Windows:** `%APPDATA%\SshTunneler\config.dat`, шифрование Windows DPAPI (`CurrentUser`)
  с дополнительной энтропией. Файл читается только из-под вашей учётной записи Windows.
- **macOS:** `~/Library/Application Support/SshTunneler/config.dat`, AES-256-GCM. Случайный
  ключ лежит в связке ключей входа (Keychain, элемент `SshTunneler` / `config-key`), а не рядом
  с файлом. С Keychain приложение работает через `/usr/bin/security`, поэтому обновление
  приложения не вызывает повторных запросов доступа к связке ключей.

Passphrase и пароли не хранятся нигде больше. Запись атомарная: сначала временный файл,
потом подмена с сохранением предыдущей версии в `.bak`. Если основной файл пропал или не
расшифровывается, приложение берёт `.bak`. Файл, который не удалось расшифровать
(повреждён, скопирован с другой машины, ключ удалён из Keychain), переименовывается
в `config.dat.corrupt-<дата>`, а приложение стартует с пустой конфигурацией. Если же
недоступна сама связка ключей (заблокирована, доступ отклонён), файл не трогается.

## Как это работает

Туннели поднимаются системным OpenSSH (`ssh.exe` из состава Windows, `/usr/bin/ssh` на macOS):
один скрытый процесс на ресурс,
`ssh -N -T -L 127.0.0.1:<local>:<remoteHost>:<remotePort> user@host`
с `ExitOnForwardFailure=yes`, `ServerAliveInterval=15`, `StrictHostKeyChecking=accept-new`.
За счёт этого работают ваши `~/.ssh/config`, ssh-agent, `ProxyJump` и остальные
привычные настройки OpenSSH.

Туннель считается поднятым, когда процесс жив и локальный порт появился в списке
слушателей (`GetActiveTcpListeners`) — проверка не открывает соединение, поэтому
не порождает лишних каналов. Дальше состояние проверяется каждые 5 секунд.

### Пароли и passphrase

ssh не читает секреты из stdin, но поддерживает `SSH_ASKPASS` и
`SSH_ASKPASS_REQUIRE=force`. Приложение назначает себя обработчиком askpass:

1. Для каждого запуска ssh создаётся одноразовый токен, в окружение дочернего процесса
   кладутся имя приватного named pipe (на macOS — Unix-сокет во временной папке
   пользователя) и этот токен.
2. Когда ssh нужен пароль или passphrase, он запускает тот же исполняемый файл приложения,
   передавая только текст приглашения. Приложение видит токен в своём окружении,
   переходит в режим хелпера, забирает секрет по pipe и печатает его в stdout.
3. Сервер pipe отдаёт секрет, только если клиент запущен под тем же пользователем
   (Windows-SID или uid на macOS) и предъявил валидный токен.
4. Если секрет не сохранён (2FA, одноразовый код, подтверждение ключа хоста),
   хелпер показывает маленькое окно ввода.

Секрет никогда не попадает ни в командную строку, ни в переменные окружения.

## Структура

```
src/SshTunneler/
  Program.cs            точка входа: режим askpass, single instance
  App.axaml(.cs)        композиция: конфиг, менеджер туннелей, окно, трей
  Models/               SshServer, TunnelResource, UiSettings, AppConfig, TunnelStatus
  Services/
    ConfigStore.cs      зашифрованный JSON, атомарная запись, карантин битого файла
    ConfigProtectors.cs DPAPI на Windows, AES-GCM + Keychain на macOS
    SshArgumentBuilder  сборка аргументов ssh (покрыто тестами)
    PortAllocator       свободные порты и проверка слушателей
    SshTunnelProcess    один процесс ssh + кольцевой буфер лога
    TunnelManager       статусы, health-check, автопереподключение
    AskPassServer/Client канал выдачи секретов для ssh
    AutoStartService    автозапуск: ключ Run на Windows, LaunchAgent на macOS
    SshMessages         человеческие формулировки ошибок ssh
    TrayIconService     иконка в трее / строке меню (рисуется в рантайме)
  ViewModels/           MainViewModel, ResourceItemViewModel, SettingsViewModel
  Views/                MainWindow (прозрачное окно), SettingsWindow, MessageDialog
  Themes/Dark.axaml     тёмная тема поверх Fluent
installer/
  build-msi.ps1         MSI для Windows
  build-macos.sh        .app и .dmg для macOS
tests/SshTunneler.Tests/  тесты, включая интеграционные; гоняются на Windows и macOS
```

## Установка

### Windows

Готовый установщик — на странице релизов:
[SshTunneler-1.0.0-win-x64.msi](https://github.com/m0nnok/ssh-tunnels/releases).
Установка идёт от имени пользователя, без прав администратора и без UAC:
приложение попадает в `%LOCALAPPDATA%\Programs\SshTunneler`, ярлык — в меню «Пуск».
Сборка self-contained, .NET на машине не нужен. Удаление — как у обычной программы,
конфигурация в `%APPDATA%\SshTunneler` при этом сохраняется.

### macOS (Apple Silicon)

`SshTunneler-<версия>-osx-arm64.dmg` собирается в GitHub Actions (артефакт сборки)
или локально скриптом `installer/build-macos.sh`. Откройте dmg и перетащите
SSH Tunneler в «Программы». .NET на машине не нужен.

Приложение подписано ad hoc, без сертификата Apple Developer, поэтому скачанную копию
macOS при первом запуске заблокирует. Снимите карантин один раз:

```bash
xattr -dr com.apple.quarantine /Applications/SshTunneler.app
```

или откройте «Системные настройки → Конфиденциальность и безопасность» и нажмите
«Всё равно открыть».

Особенности macOS:

- Приложение живёт в строке меню, иконки в Dock нет. Повторный запуск из Finder
  показывает окно.
- Автозапуск — LaunchAgent `~/Library/LaunchAgents/io.github.m0nnok.sshtunneler.plist`;
  macOS покажет уведомление о новом фоновом объекте, отключить его можно и в
  «Основные → Объекты входа».
- При первом подключении к серверу в локальной сети macOS 15+ спросит разрешение
  на доступ к локальной сети — без него ssh получит «No route to host».
- ssh-agent и `~/.ssh/config` работают как в терминале; переменные из `~/.zshrc`
  приложению, запущенному из Finder, не видны (используйте `IdentityAgent` в ssh config).

## Сборка и запуск

```bash
dotnet build SshTunneler.slnx -c Release
```

```bash
dotnet test SshTunneler.slnx
```

Готовый исполняемый файл: `src/SshTunneler/bin/Release/net10.0/SshTunneler.exe`
(на macOS — `SshTunneler` там же; `dotnet run --project src/SshTunneler` тоже работает).
Первый запуск открывает пустое окно — нажмите шестерёнку, добавьте сервер и ресурсы.

Аргументы командной строки: `--minimized` (стартовать в трее),
`--askpass` (служебный режим для ssh, вручную не нужен).

Собрать установщик (нужен WiX 5: `dotnet tool install --global wix --version 5.0.2`):

```bash
powershell -ExecutionPolicy Bypass -File installer/build-msi.ps1 -Version 1.0.0
```

MSI появится в `artifacts/`.

Собрать `.app` и `.dmg` для macOS (на Mac с .NET 10 SDK):

```bash
installer/build-macos.sh 1.1.0
```

Для Intel-маков вторым аргументом передайте `osx-x64`. Результат —
`artifacts/SshTunneler-1.1.0-osx-arm64.dmg`. Workflow
`.github/workflows/build.yml` запускает этот же скрипт на раннере macOS (Apple Silicon) после тестов.

## Тесты

Помимо модульных тестов есть интеграционные, которые запускают настоящие бинарники:

- `ssh-keygen` с `SSH_ASKPASS`, указывающим на приложение, — проверяет, что системный
  OpenSSH (Windows или macOS) действительно вызывает хелпер и получает passphrase через pipe;
- `TunnelManager` против заведомо мёртвого адреса — проверяет, что ошибка
  распознаётся, лог сохраняется, а занятый локальный порт отсекается до запуска ssh.
